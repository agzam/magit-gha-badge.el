* magit-gha-badge

[[https://github.com/agzam/magit-gha-badge.el/actions/workflows/run-tests.yml][https://github.com/agzam/magit-gha-badge.el/actions/workflows/run-tests.yml/badge.svg]]

A README-style GitHub Actions status badge in the magit status buffer.

#+begin_example
Checks   🟢 CI 0ecbb23 - 5 minutes ago
#+end_example

A section at the top of =magit-status=, fetched asynchronously from the GitHub API (via [[https://github.com/magit/ghub][ghub]]) on every status refresh - the refresh never waits on the network. =RET= or =mouse-1= on the badge opens the runs in a buffer, described under Runs below. =C-c C-o= on it opens the newest workflow run page in the browser; =M-x magit-gha-badge-browse-run= does the same from any buffer in the repo. Both refetch before they open anything, so a run that started after the last refresh is the one you land on. No steady-state timers: a bounded poll (=magit-gha-badge-poll-interval=, 30s) runs only while a run is pending and the status buffer stays displayed, then dies.

Glyphs: 🟣 queued · 🟡 in progress · 🟢 success · 🔴 failure · ⚪ cancelled/skipped · 🟠 action required. A branch with no runs shows nothing, and a failed fetch adds ❗ and the reason: =Checks   ❗ 401 Bad credentials=.

The age is when the run started, counted in magit's own units - the ones the log margin uses. It is as fresh as the line: a status buffer left open says what it said at the last refresh.

** Jobs

While a run is going, each running job gets a line with the step it is on, and each failed job a line with the step that failed:

#+begin_example
Checks   🟡 Run Tests 6bd5870 - 24 seconds ago
         🔴 Testing (29.4) - Run tests
         🟡 Testing (31.1) - Install dependencies
#+end_example

Failed jobs come first, and past five jobs the last line counts the rest. Succeeded, cancelled and queued jobs stay hidden, so a finished red run keeps only the jobs that broke, and a green run goes back to the single line. =TAB= collapses the job lines; =RET= on one opens that job in the runs buffer, =C-c C-o= its page.

** Runs

=RET= on the badge, or =M-x magit-gha-badge-runs= from any buffer in the repo, opens the workflow runs of the branch in a buffer: runs, their jobs, the steps of a job and the log of a step, each a section that folds.

#+begin_example
agzam/remoto.el  main  3fccf0c

✗ Release 2.9.1  Run Tests #464                 1m 57s
  Triggered via push 8 days ago · agzam pushed 3fccf0c main · Status Failure
  ✓ integration-tests (29.4)                       35s
  ✗ unit-tests (29.4)                           1m 53s
    ✓ Set up job                                    2s
    ✗ Run unit tests                               13s
      1  Run make test
      4  Running 3 specs.
      5  Error: Process completed with exit code 2.
#+end_example

A failed job opens at its failed step. A run in progress updates by itself, and with point in a running job the log of each step appears as the step ends. =TAB= folds, =g= asks GitHub anew, =C-c C-o= opens the page of the line at point, =C-c C-w= copies its address, and =C-c C-t= shows the time of each log line.

On a commit in a magit log the command shows that commit's runs. With a prefix argument it reads =OWNER/REPO=, =OWNER/REPO@REF= or the link of a run, so it works for any repository.

Set =magit-gha-badge-runs-unfold-jobs= to have every job show its steps when the buffer opens.

** remoto.el

[[https://github.com/agzam/remoto.el][remoto.el]] opens GitHub repositories as directories, without cloning them. The two packages integrate: with both installed, remoto.el opens workflow runs in the runs buffer.

** Forks

Work on a fork usually runs nowhere in the fork: GitHub keeps Actions off in forks by default, and the checks of a pull request run in the upstream repo. So for a fork the badge asks the upstream repo too, and shows whose run it found:

#+begin_example
Checks   🟠 Lint 1479d25 (cli/cli) - 2 hours ago
#+end_example

Only runs whose head repo is your fork count, so a branch that shares its name with one of the upstream's own (=main=, =master=) does not pick up somebody else's run.

** Install

Not on MELPA (yet). With elpaca:

#+begin_src emacs-lisp
(use-package magit-gha-badge
  :ensure (magit-gha-badge :host github :repo "agzam/magit-gha-badge.el")
  :defer t
  :init
  (with-eval-after-load 'magit
    (magit-add-section-hook 'magit-status-sections-hook
                            #'magit-gha-badge-insert
                            'magit-insert-status-headers
                            'append)))
#+end_src

** Auth

Requests go through =ghub-request= with =magit-gha-badge-auth= (default =ghub=, the generic ghub token): an authinfo entry like

#+begin_example
machine api.github.com login USER^ghub password TOKEN
#+end_example

plus =github.user= set in git config. If you already use forge, you have the stack working; see ghub's manual for token setup.

** Freshness

The badge asks GitHub for the latest run on the current branch at fetch time, so it is correct no matter who pushed - magit, a script, another machine.

A push is the one case where the answer lags. GitHub creates the run seconds after the push lands, so the refresh magit does right after a push still gets the previous run. A trailing ellipsis marks that - the run on the badge is older than the commit you pushed - and the badge polls up to three more times for the new run to appear:

#+begin_example
Checks   🟢 CI 0ecbb23 - 3 days ago ⋯
#+end_example
